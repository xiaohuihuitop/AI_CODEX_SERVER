# 实施与验证计划

## 阶段一：协议正确性与契约测试

1. 为 Desktop 内置 `codex.exe` 增加版本发现与 App Server Schema 生成/校验脚本，产物放入测试约定目录。
2. 重构 `CodexAppServerClient` 的消息分类，补齐 `initialized`、主动请求响应和关闭时待处理请求清理。
3. 为 `turn/start` 增加 `clientUserMessageId`，打通 Web/App、relay、Agent 的稳定请求 ID。
4. 增加重复控制请求测试、乱序响应测试、主动请求测试和握手顺序测试。

阶段门禁：上述测试全部通过后，才允许接入实时事件；协议不兼容时停止，不增加其他控制通道。

## 阶段二：实时事件和状态收敛

1. 在 Agent 中规范化 App Server 通知，生成带序号的统一事件。
2. relay 增加事件去重、有限窗口、序号确认和目标设备广播。
3. Web/uni-app 增加事件 reducer，按事件更新当前回合内容与五层状态。
4. 连接重建或序号空洞时调用目标线程快照对账，清除重复过程块和陈旧“进行中”。
5. 增加结构化日志并保持 500 条上限。

阶段门禁：模拟丢事件、重复事件、乱序事件和断线重连，最终消息与状态必须一致。

## 阶段三：Desktop 来源变化优先同步

1. 保持 SQLite 未归档目录逻辑不变，为 JSONL 增加变化线程优先队列。
2. 调整同步调度顺序：待确认控制、变化线程、常规轮询。
3. 目录校验时物理移除归档线程及其 relay 快照。
4. 为 150 个以上线程构造负载测试，验证目标线程变化不等待全量轮询。

阶段门禁：变化线程 5 秒内完成上传，归档线程不再出现，监听遗漏能由周期校验发现。

## 阶段四：历史游标和跨端验收

1. relay 历史接口改用稳定 `turnId` 游标，默认和增量均为 5 轮。
2. Web/uni-app 按 ID 合并分页，保留最新窗口与滚动位置。
3. 在 `codex_temp` 选定同一线程执行真实链路：连续发送 3 条、接收增量与完成、停止回合、断线重连、加载更早历史。
4. 验证 Desktop 来源新消息和归档操作同步。
5. 运行全部测试、静态检查和 Windows 管理器构建；不打包手机 App。

## 测试矩阵

| 场景 | 预期 |
| --- | --- |
| 初始化 | `initialize` 后恰好一个 `initialized` |
| 主动请求 | 被处理或明确拒绝，不静默挂起 |
| 重复发送 | 同一消息 ID 最多一个回合 |
| 实时增量 | Web/App 无手动刷新可见 |
| 完成/失败/停止 | 等待计时立即停止，状态一致 |
| 事件重复/乱序 | 去重或对账，无重复过程块 |
| relay 断线 | 重连发现序号空洞并恢复快照 |
| Desktop 新内容 | 5 秒内进入优先同步 |
| 归档线程 | 列表与缓存均删除 |
| 加载更早历史 | 每次 5 轮，不覆盖最新内容 |

## 文档与规范回填

完成后更新 `.trellis/spec/backend/codex-control-plane.md`：历史和状态投影从单一 JSONL 模式调整为“Agent 来源事件实时主链路 + JSONL 最终对账，Desktop 来源 JSONL 观察”，同时保留 App Server 唯一控制平面和 SQLite 唯一可见目录的约束。

## 回滚原则

每个阶段独立提交。回滚只允许撤销当前阶段代码；不得恢复 CDP、旧 CLI、重启 Codex 或自动批准作为替代实现。

## 实施结果

- JSON-RPC 握手、主动请求分类、请求清理和运行时版本上报已完成。
- Web/App、Relay、Agent 与 `turn/start` 已贯通 `clientUserMessageId`，Agent 对重复消息 ID 幂等处理。
- App Server 通知已规范为有序事件流；Relay 和客户端完成去重、序号空洞检测与权威快照对账。
- Desktop JSONL 变化线程已进入优先同步队列；常规轮转游标不受影响。
- 历史分页改为 `turn:<turnId>` 稳定游标，手机端初始和增量均为 5 轮。
- Agent 重连或事件缺失时通过 `thread/read(includeTurns=true)` 校正陈旧运行态，不使用时间猜测或 CDP 兜底。
- 发送期间的历史竞态已用发送前消息边界消除，Web 实测用户消息只显示一次。

## 验证结果

- 自动化：`npm test` 通过 174/174，`npm run check` 和 Desktop 入口语法检查通过。
- 构建：`npm run build:manager:win` 通过，固定产物为 `desktop/dist/win-unpacked/Codex Desktop 管理器.exe`。
- 真实 Web：`codex_temp` 连续发送 `RT_ACK_1` 至 `RT_ACK_5` 均自动回显；最后一次用户消息和回复各 1 条。
- 状态：Agent 断线后旧“进行中”通过 `thread/read` 收敛为完成；页面无需手动刷新。
- 停止：长输出回合在网页点击停止后收敛为完成且停止按钮禁用。
- 过程未关闭、重启或注入官方 Codex Desktop；仅为构建关闭了本项目的桌面管理器。

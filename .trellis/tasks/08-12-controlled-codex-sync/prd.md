# 重建受控 Codex 双端同步

## 目标

让手机/Web 与 Windows 官方 Codex Desktop 操作同一个受控客户端实例，实现手机控制电脑，并确保双方看到相同的线程、用户消息、运行过程、最终回复和停止状态。

## 背景与已确认事实

- 当前正式链路由 Windows Agent 另外启动 `codex.exe app-server`。官方 Codex Desktop 自己也运行独立的 App Server；两者共享本地会话文件，但不共享实时事件和内存状态，因此手机回合可以写入 JSONL 并获得回复，却不会实时出现在已经打开的官方桌面窗口。
- 旧 CDP 实现使用标题和项目名查找线程，以 DOM 图标推断运行状态，并把点击成功视为发送成功；这些判断会随 UI 变化、重名线程和异步渲染失效。
- 旧 Windows 启动器硬编码查找与结束 `Codex.exe`，并假定包内入口为 `app\\Codex.exe`。当前官方包 `OpenAI.Codex_26.707.3748.0` 的清单入口实际为 `app/ChatGPT.exe`，主进程也为 `ChatGPT.exe`。旧逻辑可能没有退出普通实例，导致后续 CDP 参数被单实例机制吞掉。
- 直接执行 `C:\\Program Files\\WindowsApps\\...\\ChatGPT.exe` 会被系统拒绝。必须通过 Windows 包应用入口启动，不能依赖直接访问受保护目录。
- 用户明确允许管理器接管、关闭、重启和控制官方 Codex Desktop。产品目标优先于“普通桌面实例不受影响”。
- Codex-Mini 的公开说明采用“受控 Codex”模式：手机输入由本地服务注入受控官方客户端，历史和状态从本地会话读取。其 Windows 完整后端未公开，只能借鉴架构，不能复制未审计实现。

## 需求

### R1 单一受控实例

- 管理器必须识别官方包清单声明的实际可执行入口和当前主进程名称，不能硬编码 `Codex.exe`。
- 启用远程功能时，管理器负责把官方客户端切换为唯一受控实例；普通实例存在时必须明确关闭并等待进程树退出，再启动受控实例。
- 受控实例必须由 Windows 包应用入口启动，并携带仅绑定 `127.0.0.1` 的 CDP 参数。
- CDP 端口必须由管理器独占。端口被其他进程占用时必须报告占用者并拒绝接管，禁止自动换端口或杀死未知进程。
- 只有 CDP 目标页握手成功且目标属于本次启动的官方实例，才能显示“会话服务就绪”。

### R2 唯一控制通道

- 手机/Web 的线程切换、发送和停止只允许进入受控官方客户端，不再启动独立 App Server 执行回合。
- 不保留 App Server 发送、CDP 发送之间的运行时 fallback；接管失败时明确失败。
- 所有会改变桌面 UI 的命令必须串行执行，并携带目标 `threadId` 和命令 ID。

### R3 精确线程与发送确认

- 线程身份以 `threadId` 为准，标题、项目名只用于展示，不能作为唯一定位键。
- 切换线程优先使用官方 `codex://threads/<threadId>` 深链接；完成切换后必须从受控页面或会话事实验证当前线程 ID。
- 发送前检查目标线程、输入框状态和本地草稿；存在草稿时拒绝远程发送，不覆盖用户输入。
- 点击发送不代表成功。只有目标线程 JSONL 出现与命令关联的新用户消息，才向手机确认“已送达”。
- 同一命令 ID 重试不得产生重复用户消息。

### R4 双端状态与历史同步

- 官方桌面页面是交互载体，本地 JSONL 是消息与终态的权威事实；CDP 图标不能作为完成状态依据。
- Agent 增量读取同一 `threadId` 的 JSONL，并通过既有 Relay WebSocket 推送用户消息、过程、最终回复和终态。
- 手机/Web 收到终态后必须自动拉取并显示最新回复，不需要手动刷新。
- 桌面手动发送、停止或归档也必须通过 JSONL/受控页面变更同步到手机。
- 线程列表只展示受控官方客户端当前侧栏可见的未归档线程；不得重新扫描全部历史制造额外线程。

### R5 可观测性与恢复

- 管理器日志必须记录版本、受控实例 PID、CDP 端口与占用者、启动阶段、目标页数量、命令 ID、线程 ID、发送确认、终态和失败原因，最多保留 500 条。
- 受控实例退出、CDP 断开或目标页更换时立即标记未就绪，不能继续接收手机控制命令。
- Agent 或管理器重启后必须重新验证现有受控实例的所有权；不能仅因为端口可访问就接管未知实例。
- 官方客户端升级导致入口、页面结构或协议变化时，必须明确显示“不兼容”，禁止猜测选择器继续操作。

## 验收标准

- [ ] 管理器可以关闭当前普通 `ChatGPT.exe` 实例，并通过包应用入口启动带 CDP 的受控实例；全过程不直接执行 `WindowsApps` 中的 EXE。
- [ ] 连续执行 5 次“重启受控 Codex”，每次都只存在一个受控主实例，端口所有权正确，目标页面握手成功。
- [ ] 在 `codex_temp` 的指定现有线程中，手机连续发送 3 条带唯一标识的消息；每条只出现一次，并在 3 秒内同时显示于官方桌面和手机/Web。
- [ ] 官方桌面连续回复 3 轮时，手机/Web 自动显示增量过程和最终回复；每轮终态在真实 JSONL 终态后 3 秒内收敛，不需要手动刷新。
- [ ] 手机停止、桌面手动停止各验证 1 轮；双方均显示停止，等待计时结束，最终状态不被后续旧事件覆盖。
- [ ] 切换两个标题相同的线程发送时，消息按 `threadId` 进入正确线程，不依赖标题匹配。
- [ ] 目标线程存在本地草稿时，手机收到明确拒绝，草稿内容保持不变。
- [ ] CDP 端口被未知进程占用、受控实例退出、DOM/协议不兼容时，系统明确失败且不启动独立 App Server 兜底。
- [ ] 自动化测试包含进程入口识别、端口所有权、命令幂等、线程验证、JSONL 发送确认、终态乱序和断链恢复；最终还需完成真实 Windows + Web 端到端测试。
- [ ] 构建产物仍固定输出到 `desktop/dist`，可执行文件名保持 `Codex Desktop 管理器.exe`。

## 非范围

- 不修改或注入官方 Codex 安装文件。
- 不允许手机直接连接 CDP 端口。
- 不实现多个控制器同时连接同一个受控实例。
- 不复制 Codex-Mini 的非公开 Windows 实现或受限许可代码。
- 本次不重新设计手机 UI，只调整连接、状态和错误呈现所需行为。

## 风险与约束

- 官方桌面 UI 和内部路由不是稳定公共 API，升级后可能需要适配；必须通过兼容性探针和真实 E2E 检测暴露变化。
- 接管会关闭普通 Codex；任何未发送草稿可能丢失。启用接管前应先检测可见草稿；无法可靠检测时必须要求用户确认，不能静默关闭。
- 项目明确禁止未确认 fallback。本任务不会保留独立 App Server 控制路径作为备用执行通道。

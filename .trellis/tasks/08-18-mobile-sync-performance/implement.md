# 实施与验证计划

## 执行规则

- 严格按阶段顺序执行；当前阶段未通过，不进入下一阶段。
- 每个缺陷先增加可复现测试，再修改实现。
- 每阶段记录耗时、请求数、事件数、内存和版本号，不能只凭界面观感判断。
- 禁止增加 fallback；如发现确实需要替代路径，停止实施并先征得用户确认。

## 阶段 0：建立可测环境

### 修改

- 不改业务逻辑，只确认公网 HTTPS/WSS、Agent、Relay、Web 和 Android 调试端使用同一设备。
- 为本任务记录结构化时间点和请求计数的测试入口，临时工具只放 `docs/temp`，验证结束删除。

### 验证

- `/codex/health` 返回 Agent 在线、同步新鲜、线程数大于 0。
- `/agent` 与 `/mobile` WebSocket 均完成 101 升级并持续在线 60 秒。
- `codex_temp` 在线程列表、官方 UI、JSONL 和 Relay 中映射为同一 `threadId`。

### 通过门槛

- 三项全部通过；否则停止在网络/鉴权/CDP 层排障，不能开始性能改造或统计端到端时延。

## 阶段 1：先锁定当前性能缺陷

### 修改

- 增加无正文的结构化诊断字段：阶段、线程 ID、回合 ID、同步版本、耗时、缓存命中和请求计数。
- 增加基准测试，覆盖 400 MB 级会话、空闲同步和手机事件突发。

### 验证

- 基准测试能稳定复现整文件读取、每秒空同步和重复刷新。
- 诊断日志不包含 Token、用户正文或附件路径。

### 通过门槛

- 基线数据可重复，测试在旧实现上明确失败；没有证据的性能猜测不进入实现。

## 阶段 2：停止空同步和刷新风暴

### 修改

- Agent 心跳与数据同步分离，无变化不发送 `session-sync`。
- Relay 只对真实变化递增版本并广播受影响线程。
- 手机增加 single-flight 和事件合并；删除 4 秒全量刷新，改为 30 秒轻量版本核对。

### 验证

- 空闲 60 秒统计同步、广播、历史和状态请求。
- 注入 100 个同线程事件和 100 个无关线程事件，统计最大并发和实际读取次数。
- 断开实时通道，确认页面显示离线且不触发控制动作。

### 通过门槛

- 满足 AC1、AC5、AC9；任一计数超标则本阶段继续修正。

## 阶段 3：建立 Relay 原子线程视图

### 修改

- 增加原子线程视图缓存与接口。
- 历史和状态普通读取取消同步 `forwardToAgent()`。
- Relay 快照应用与 `session-updated` 广播绑定同一版本。

### 验证

- 人为让 Agent 查询延迟 10 秒，已缓存线程视图仍在本地 200 ms 内返回。
- 同一响应内的历史、状态和版本相互一致。
- 快照未就绪时返回明确状态，不直穿 Agent。

### 通过门槛

- 满足 AC2；接口契约测试覆盖缓存命中、未就绪、陈旧和版本乱序。

## 阶段 4：改造大 JSONL 读取

### 修改

- 最近历史和状态改为文件尾部增量投影。
- 更早 5 轮使用稳定字节游标或稀疏偏移索引。
- 处理文件追加、尾部半行、截断、替换和缓存淘汰。

### 验证

- 新旧解析器在固定小型夹具上的消息、回合、状态结果逐字段一致。
- 使用当前 411 MB 会话分别测冷启动、热读取、旧页读取和 RSS。
- 连续追加、截断、尾部损坏后重新读取，确认无重复和无丢失。

### 通过门槛

- 满足 AC3、AC4；任何数据差异优先修正确性，不用性能目标掩盖错误。

## 阶段 5：收敛实时状态和终态

### 修改

- Agent 增加 dirty latch，目标线程出现新 JSONL 行时立即安排下一次增量同步。
- Relay 在应用目标快照后再广播版本化事件。
- 手机按 `threadId + turnId + syncVersion` 合并状态，移除固定次数终态重读。

### 验证

- 模拟重复、乱序、丢失和延迟事件，终态不被旧 running 覆盖。
- 官方回复、官方停止、手机停止各测一次，观察 JSONL 到 Web/手机终态耗时。

### 通过门槛

- 满足 AC7；三种终态均无需手动刷新。

## 阶段 6：验证发送链路

### 修改

- 保留 `202 + control-result`，移除控制完成后不必要的全量状态轮询。
- 补齐从 HTTP 接收到 JSONL 开始、Relay 应用和客户端渲染的阶段耗时。

### 验证

- 在 `codex_temp` 连续发送 3 条唯一消息。
- 每条核对同一 `clientUserMessageId`、命令 ID、`turnId`、官方 UI、JSONL、Relay 和手机/Web。
- 重复提交同一 ID 只返回既有结果，不重复执行；断网恢复不自动重发。

### 通过门槛

- 满足 AC6，且三轮恰好执行三次，不多不少。

## 阶段 7：分页和交互回归

### 修改

- 线程切换只加载最新 5 轮；上滑每次追加 5 轮。
- 请求返回前切换线程或设备时，旧请求结果不得污染新页面。

### 验证

- 连续加载 20 页，核对顺序、重复、缺失和滚动锚点。
- 覆盖长 Markdown、过程折叠、附件提示、草稿禁止切换和多设备切换。

### 通过门槛

- 满足 AC4，且既有移动端功能测试全部通过。

## 阶段 8：完整质量门禁与发布

### 验证顺序

1. 相关单元与集成测试。
2. 全量 `npm test` 和 `npm run check`。
3. 桌面管理器构建，固定输出到 `desktop/dist/Codex Desktop 管理器.exe`。
4. 本地 Relay 端到端。
5. 公网 Web 在 `codex_temp` 执行 AC8。
6. Android HBuilderX 真机执行同一组 AC8，并记录网络请求数和时间点。
7. 连续运行 30 分钟，确认无请求堆积、内存持续增长、重复消息或错误状态。

### 通过门槛

- AC1 至 AC10 全部有实测记录。
- 任何自动化、Web、Android 真机或产物检查失败都不提交、不打 Tag、不推送。
- 全部通过后按“服务端 -> 桌面管理器 -> 手机 App”的顺序交付，再提交、推送并触发 Docker 镜像构建。

## 2026-08-18 实施记录

### 已完成

- Agent 心跳与会话同步已分离；空载荷不再发送 `session-sync`，同步期间的新变化由 dirty latch 合并处理。
- Relay 仅在目录、线程快照或控制确认真实变化时递增版本，并提供同版本的原子线程视图。
- 手机与 Web 已改为按变化线程刷新，当前线程读取使用 single-flight；前台轮询降为 30 秒轻量健康与版本核对。
- 最近历史和状态使用有界尾部读取；旧页使用反向分页，避免普通查询完整解析大型 JSONL。
- 桌面管理器版本更新为 `v0.3.19`，固定目录构建与产物版本检查通过。

### 实测结果

- 约 424 MB 真实 JSONL：冷读取最近 5 轮 749 ms，热读取 29 ms，共享状态读取 28 ms，RSS 增量 54 MB。
- 本地真实 Web 页面连续发送 3 轮，三轮回复均约 1.5 秒自动出现，输入框自动清空并切换为已完成，无需手动刷新。
- 三轮请求统计：线程列表 1 次、原子线程视图 7 次、发送 3 次、状态 3 次，未出现刷新风暴。
- 自动化测试 243/243 通过，静态检查、`git diff --check` 和桌面管理器构建通过。
- 新版本机 Agent 已恢复运行；公网健康检查确认云端在线、Agent 在线、同步新鲜。

### 未完成门禁

- Android ADB 当前没有连接设备，因此 Android 真机发送、停止、自动终态和 30 分钟稳定性尚未验证。
- 新 Relay 代码尚未部署到公网，公网 Web 与 Android 还不能验证原子线程视图协议。
- 在以上两项通过前，不满足 AC8、AC10，不提交、不打 Tag、不推送发布。

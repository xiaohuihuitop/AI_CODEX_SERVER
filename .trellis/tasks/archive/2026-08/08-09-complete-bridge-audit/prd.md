# 完整验证跨端接管与缓存清理

## 目标

以用户真实使用路径为标准，完整验证手机/Web、云端 Relay、Windows Agent、Codex App Server 与本地会话之间的收发、列表、历史和状态一致性；修复归档或删除线程只隐藏、不清除服务器缓存的问题，并处理验收过程中发现的同类缺陷。

## 硬性需求

- 手机/Web 必须控制电脑端同一 `threadId`，发送、停止只使用 Codex Desktop 内置 App Server。
- 线程从电脑端侧栏归档或删除后，Agent 下一次上传权威 `openThreadIds` 时，Relay 必须在同一个同步请求内物理删除该线程的内存缓存。
- 权威列表为空数组时必须清空该 Key 的全部会话缓存；同步包未携带 `openThreadIds` 时不得根据局部增量误删缓存。
- 被清除线程的列表、历史和状态接口均不得继续返回旧内容；线程重新打开后允许按新快照重新建立缓存。
- 多台电脑继续使用不同 Key 隔离；本任务不实现手机端统一设备切换入口。
- 不同步、不展示电脑端或手机端未发送草稿。
- 手机/Web 自动接收新消息和状态，不依赖手动刷新；同步过期时必须显示未确认，等待时间不得无限增长。
- 默认加载最近 5 轮，上滑每次加载更早 5 轮；顺序固定为用户消息、公开处理过程、最终回复，且不得重复过程卡片。
- 附件只保留数量提示，不上传内容，不暴露电脑本地路径。
- 日志应覆盖列表同步、控制命令、App Server 回合和同步确认，最多 500 条并支持清除。
- 不得新增会掩盖错误、自动重发、切换控制通道或重启 Codex Desktop 的 fallback。

## 验收标准

- [x] 回归测试能稳定复现“线程退出权威列表后仍可读取旧缓存”，修复后同一测试通过。
- [x] `openThreadIds: []` 在同一次 `applySync` 中清空对应 Key 的会话对象。
- [x] 未提供 `openThreadIds` 的局部同步不删除其他线程。
- [x] 不同 Key 的清理、历史、状态和在线 Agent 完全隔离。
- [x] 归档线程的列表、历史、状态均不可再读取，重新同步后可重新出现。
- [x] 自动化覆盖发送确认、停止、状态新鲜度、乱序响应、重复记录、历史分页和附件过滤。
- [x] 至少执行一次真实 Web 同线程收发，核对目标 `threadId`、本地 JSONL 用户消息、最终回复和 Web 回显。
- [x] 明确记录 Codex Desktop 当前窗口实时显示是否可自动验证；不能用 JSONL 成功替代该项结论。
- [x] 完整测试、静态检查、Windows 管理器构建和 `app.asar` 控制平面校验全部通过。
- [x] 所有临时诊断产物删除，发现的长期约束写入项目规范。

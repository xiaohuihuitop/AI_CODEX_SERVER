# 优化 Windows Agent 远程桥接

## 目标

在保留 Windows Codex Desktop App 作为现有对话运行时的前提下，使手机端能够可靠地继续多个已打开对话、快速下发消息，并实时显示每个对话的运行状态。

## 已确认事实

- Windows Agent 通过 WebSocket 主动连接云端 Relay，CDP 仅监听本机 `127.0.0.1:9229`。
- 手机端当前以 1.5 秒、2 秒和 0.9 秒分别轮询连接、线程和运行状态；Agent 默认每 2 秒同步会话增量。
- 发送和停止操作经 Relay 转发到 Agent，再由 PowerShell CDP 脚本控制 Codex Desktop。
- 控制脚本目前按项目名和对话标题选择第一条匹配项，并且未检测已有草稿或发送按钮禁用状态。
- 当前协议不会把 Codex Desktop 编辑器草稿上传到手机。CDP 可以读取当前编辑器文本，但读取多个对话的草稿需要切换 Desktop UI，可能干扰电脑端正在进行的工作。
- 本任务不迁移到 App Server，不放弃 Codex Desktop App，也不承诺接管未在 Desktop 中打开的线程。

## 范围

### 本次包含

- 为 Agent 控制操作建立串行队列，避免 `send`、`stop` 并发争抢 Codex Desktop UI。
- 为远程发送与停止补充目标线程校验、明确命令状态和可识别错误。
- 将停止操作绑定到指定线程，避免停止错误的前台对话。
- 更新手机 App 与现有静态网页客户端，使其都按新协议传递停止目标线程。
- 使用 Agent 推送的会话更新驱动手机端刷新，降低常态轮询并缩短状态可见延迟。
- 为 Agent 与 Relay 增加存活检测、断线状态和可观察的最后同步时间。
- 补充对应的单元与集成测试，修复根目录工程元数据导致的脆弱测试。

### 本次不包含

- 替换 Codex Desktop App 或迁移现有对话至 Codex App Server。
- 支持 iOS、多用户协作、多设备同时控制同一个 token。
- 改造会话内容解析模型或长期持久化云端会话。
- 变更用户的 Codex Desktop 账号、模型、权限或本地项目数据。

## 需求

### R1 控制正确性

- 同一时刻只允许一个会触碰 Codex Desktop UI 的控制操作执行。
- `send` 必须精确定位目标线程；发现同项目下标题不唯一或目标不可操作时，必须拒绝命令并返回明确错误。
- `stop` 必须接收目标线程 ID，并只对该线程执行停止操作。

### R2 本地编辑保护

- 远程发送前必须检测目标线程的本地草稿和发送控件状态。
- 不得静默清空、覆盖或拼接本地未发送草稿。

### R3 实时状态

- Agent 接收到会话增量后立即通知 Relay，Relay 将线程状态变更推送给已连接手机端。
- 手机端在页面可见期间保持一条实时订阅连接；断开后应明确展示连接状态并重连。
- 手机端应继续支持主动刷新，但不再依赖高频状态轮询获得运行中、完成和错误状态。

### R4 可观测性与恢复

- Relay 识别失活 Agent，避免显示“在线但命令超时”。
- 管理器和手机端能显示 Agent 在线状态及最后成功同步时间。
- Agent 断线重连不能与失活旧连接永久冲突。

## 验收标准

- [ ] 连续快速发起两条控制命令时，Windows Agent 按顺序执行，CDP 脚本不会并行运行。
- [ ] 对话标题重复、目标线程不存在、存在本地草稿或发送按钮不可用时，手机端收到明确失败结果，Codex Desktop 内容不被错误修改。
- [ ] 手机端停止指定对话时，不会停止另一个前台对话。
- [ ] 新的运行状态在 Agent 同步后通过推送到达手机端，无需 0.9 秒状态轮询。
- [ ] Agent 失活或连接替换后，Relay 在有限时间内将其标记离线，后续连接可恢复。
- [ ] `server` 测试和检查命令通过，且根目录工程元数据不再导致测试失败。

## 关键决策

- 草稿策略：仅在即将远程发送的目标线程检测“存在本地草稿”，随后拒绝发送；不上传、展示或编辑草稿正文。
- 事件策略：手机端通过 Relay 的实时连接接收会话更新通知，再按需从现有缓存 API 获取线程、历史和状态快照。
- 兼容策略：保留现有 HTTP API 和 Codex Desktop CDP 控制路径，不迁移至 App Server。

# Windows Agent 远程桥接执行计划

## 实施顺序

1. 修复并测试 `DesktopAgentApi` 的 FIFO 控制队列。
2. 扩展 PowerShell CDP 脚本：线程唯一性校验、草稿检测、发送按钮校验，以及按线程停止。
3. 将 `threadId` 贯穿手机 API、静态网页客户端、Relay、Agent API 和控制器的停止协议。
4. 在 Agent 成功处理发送或停止后立即同步会话。
5. 在 Relay 实现 Agent 心跳、手机 WebSocket 注册和状态事件广播。
6. 在 Android App 实现实时订阅、事件驱动刷新、最后同步时间展示，并移除高频线程与状态轮询。
7. 更新桌面管理器状态呈现与根目录白名单测试。
8. 增加单元、Relay 集成和移动端静态行为测试。
9. 为 Relay 缓存增加同步版本、新鲜度租约与超时广播；手机客户端按版本忽略旧快照。
10. 将发送/停止本地等待改为有确认窗口的命令状态，超时后显示未确认并冻结等待时长。
11. 以 `turnId` 校验处理过程与最终回复顺序，覆盖 Agent 假在线、同步停滞、旧响应乱序和过程未关联测试。

## 重点验证

- 控制队列的顺序、失败释放和停止目标传递。
- 草稿、禁用发送按钮、重复标题和缺失线程均不会触发输入操作。
- Agent `session-sync` 后手机客户端收到事件；断线、心跳超时和重连后状态正确。
- 手机页面隐藏或销毁时关闭实时连接，旧事件不会回写页面。
- `npm test` 与 `npm run check` 在 `server/` 通过。
- PowerShell 脚本通过现有语法检查。
- Agent WebSocket 保持在线但停止同步时，手机在租约到期后不再显示运行计时。
- 发送后未产生对应新快照时，手机在确认窗口到期后显示未确认，且不会无限等待。
- 同一轮过程卡片始终在对应最终回答之前；未关联过程不得显示在最终回答之后。

## 风险文件

- `desktop/scripts/win-codex-control.ps1`：误操作风险最高，必须先补测试再改行为。
- `desktop/src/desktop-agent-api.js`：控制队列影响所有 UI 自动化命令。
- `server/src/cloud-relay.js`：WebSocket 路由和心跳影响 Agent、手机端连接。
- `app/pages/index/index.vue`：生命周期、请求取消和实时连接容易引入旧事件回写。

## 回滚点

- Relay 事件连接可以独立关闭，HTTP 缓存查询仍可工作。
- 手机端实时订阅可以独立移除并恢复原有刷新节奏。
- 控制安全校验与队列保留，避免回滚后重新引入误发风险。

# 跨平台与干净检出检查指南

## 适用范围

- 修改 CI、仓库目录结构、构建入口或依赖固定目录存在的测试时，必须执行本指南。
- Windows 本机测试通过不能替代 Linux CI 或干净检出验证。

## 仓库状态契约

- Git 不跟踪空目录。运行时或测试必须存在的目录，需要跟踪占位文件，或由受测入口显式创建。
- 临时目录应忽略实际内容，同时通过否定规则保留占位文件，例如：

```gitignore
docs/temp/*
!docs/temp/.gitkeep
```

- 不得依赖本机未跟踪文件、历史构建产物、全局依赖或预先存在的目录让测试通过。
- 解析固定平台路径时必须使用对应实现；例如在任意宿主系统解析 Windows 安装目录时使用 `path.win32`，不得使用随宿主变化的 `path` 默认方法。
- 新增仓库结构断言后，必须确认目标文件已被 Git 跟踪：

```powershell
git ls-files docs/temp/.gitkeep
```

## 必需验证

1. 在当前工作区执行目标回归测试、完整测试和静态检查。
2. 从当前提交创建全新克隆，不复制工作区未跟踪文件。
3. 在新克隆中按 CI 顺序安装依赖并执行相同命令。
4. 验证完成后删除 `docs/temp` 下的临时克隆和诊断产物。

## 诊断矩阵

| 现象 | 优先检查 |
| --- | --- |
| 本机通过、干净克隆失败 | 未跟踪目录、文件、依赖或环境变量 |
| Windows 通过、Linux 失败 | 路径大小写、分隔符、进程模型和 Shell 差异 |
| 归档副本出现文件名异常 | 不使用 Windows `tar` 结果代替干净 Git 克隆 |
| CI 在构建前失败 | 先复现具体测试断言，不进入 Docker 构建排查 |

## 已知回归

- `server/test/entrypoints.test.js` 会校验 `docs/temp` 存在。该目录必须通过 `docs/temp/.gitkeep` 保留，防止本机已有空目录掩盖干净检出失败。
- `findDesktopCodexExecutable()` 在 Linux CI 中仍需解析 Windows 安装路径，必须使用 `path.win32.join()`，不能由 runner 平台决定分隔符。

# 手机端状态管理

## 总体约定

手机端使用 Vue 组合式 API 保存页面内存状态，使用 `app/utils/config.js` 管理需要跨页面和跨启动保留的本地配置，不引入全局状态库。

## 状态分类

- 设备配置：版本化存储在 `codexMobile.devices.v1`，以稳定设备 ID 为主键。
- 设备选择：每个设备独立保存最后选择的项目和对话。
- 页面状态：线程、消息、运行状态、加载状态和草稿只保存在首页实例。
- 服务器状态：HTTP 快照与 WebSocket 事件共同更新，最近健康检查只用于提示，不代表持续实时在线。

## 设备切换事务

设备切换必须按以下顺序执行：

1. 检查未发送草稿，存在草稿时拒绝切换。
2. 废弃当前生命周期令牌，停止轮询和重连，关闭旧 WebSocket，取消旧 HTTP 请求。
3. 清空旧设备的线程、消息、运行状态和分页状态。
4. 写入目标设备 ID，加载目标设备配置和设备级选择。
5. 获取目标设备健康状态、线程、历史和状态，再建立实时连接。

切换失败不得自动回退旧设备，也不得尝试其他 Token。

## 异步隔离

所有可能跨越设备切换的异步回调都必须同时校验：

- 页面生命周期令牌仍匹配。
- 回调捕获的设备 ID 仍是当前设备。
- WebSocket 回调还属于当前 Socket 实例。

只校验页面是否可见不足以防止旧设备数据回写。

## 待确认消息与权威历史

手机/Web 发送后的本地气泡只是展示投影，电脑 JSONL 经 Agent 返回的历史才是权威事实。两者必须保持单向合并：

1. 发送前的 `baseMessageCount` 只统计权威历史，不统计 `local-user-*`、`local-assistant-*` 或 `pending=true` 的临时消息。
2. 每次合并前先从输入列表剔除全部本地临时消息，再根据待确认记录重新生成展示气泡；不得直接把上一次渲染结果当成权威历史继续合并。
3. 只有电脑历史中出现不带本地标记的同一用户消息，才能移除待确认记录。控制结果只能绑定 `turnId` 或记录明确失败，不能自行证明历史已经同步。
4. Relay 已受理后，HTTP 超时或实时确认延迟不得把文本恢复到输入框。明确失败保留原用户气泡并显示失败原因，避免用户误以为需要重新发送。

回归测试必须覆盖：立即发送、同一展示列表重复合并、实时控制结果晚于 HTTP、权威历史最终替换临时气泡，以及输入框始终不回填已提交文本。

## 常见错误

- 使用设备名称作为主键，重命名后导致选择状态丢失。
- 只替换 Token，不关闭旧请求、轮询和 WebSocket，导致设备串线。
- 将最近一次健康检查显示为实时在线。
- 新配置损坏时读取旧配置兜底，掩盖数据问题并产生双配置源。
- 持久化草稿正文；当前项目只持久化草稿存在标识用于跨页面保护。
- 用已包含本地临时气泡的展示列表再次执行历史去重，使乐观消息自我确认并在下一次刷新时消失。

# Codex Windows Bridge 使用说明

## 目标

在 Windows 上提供一个局域网 Web 控制端，让手机浏览器可以查看 Codex Desktop 线程、读取历史消息，并把输入发送到电脑端 Codex Desktop。
页面使用两级选择：先选择 Codex Desktop 中打开的项目文件夹，再选择该项目下打开的对话。

## 三端目录

当前工程按端拆分，互不共用正式入口文件：

```text
desktop/  Windows 桌面管理器、本机 Agent、本机网页
server/          云端 relay、Docker、云端网页
app/      Android uni-app 手机端
```

根目录只保留统一测试和开发聚合命令。日常开发某一端时，优先进入对应目录操作。

## 实现方式

- Windows Agent 读取 Codex Desktop 的本地线程目录，再用 `%USERPROFILE%\.codex\sessions` 和 `%USERPROFILE%\.codex\session_index.jsonl` 匹配 threadId 和历史消息。
- 云端模式下，Windows Agent 主动把当前打开线程的 JSONL 尾部和后续增量上传到云端；云端解析并缓存 `threads/history/status`，手机端只读取云端缓存。
- 同一个项目文件夹下可以显示多个当前打开对话。
- 手机端页面通过 HTTP API 调用本机服务或云端缓存接口。
- 手机端消息使用本地 Markdown 渲染器展示标题、列表、引用、代码块、链接和表格。
- 手机端使用灰色或绿色状态点显示当前选择对话是否正在工作。
- 发送和停止消息时，Windows Agent 直接启动 Codex Desktop 当前安装版本附带的 `codex.exe app-server`，通过 JSON-RPC stdio 恢复目标 threadId 并发起回合。
- 不能使用 PATH 中的 npm 全局 CLI 代替内置 `codex.exe`，否则新版本 Codex Desktop 写入的会话格式可能无法恢复。
- 云端模式下，发送消息和停止回复仍由云端转发给 Windows Agent 执行；读取线程、历史和状态不再转发给 Agent 实时解析。

## 前置条件

- Windows 环境。
- Node.js 20 或更高版本。
- 已安装 Windows 版 Codex Desktop。
- 正常同步、发送和停止不需要开放 CDP；只需已安装并可正常运行 Windows 版 Codex Desktop。
- 本机局域网模式要求手机和电脑处在同一个局域网；云端模式只要求手机、电脑 Agent 都能访问同一个云端 relay。

## 启动

### Windows 桌面管理器

正式桌面入口使用 Electron 小工具。进入电脑端目录执行：

```powershell
cd desktop
npm install
npm run start:manager:gui
```

窗口名称为 `Codex Desktop 管理器`，用于配置云端服务器地址、固定 Token、设备名称，并启动或停止 Windows Agent。
如果 App Server 未就绪，先检查 Codex Desktop 是否安装且能正常打开，再查看管理器日志中的内置 `codex.exe` 路径和启动错误。管理器不会关闭、重启或附加调试参数到 Codex Desktop。

Agent 默认每 `1000ms` 上传当前打开线程的新增 JSONL 行。首次看到某个打开线程时，只上传尾部 `1000` 行，避免一次读取和上传完整历史文件。
Agent 每 `1000ms` 轻量核对 Codex Desktop 侧栏线程成员，归档或删除会在下一次同步中触发云端物理清理；未匹配到本地会话文件的线程默认每 `10000ms` 重试一次完整映射。
可通过环境变量调整：

```powershell
$env:CODEX_AGENT_SYNC_INTERVAL_MS="1000"
$env:CODEX_AGENT_CATALOG_CHECK_INTERVAL_MS="1000"
$env:CODEX_AGENT_DISCOVERY_INTERVAL_MS="10000"
$env:CODEX_AGENT_INITIAL_SYNC_LINES="1000"
```

### 构建 Windows 可执行文件

进入电脑端目录执行：

```powershell
cd desktop
npm run build:manager:win
```

构建产物输出到 `desktop\dist` 目录。免安装版本可直接运行 `desktop\dist\win-unpacked\Codex Desktop 管理器.exe`。

### 本机局域网服务

进入电脑端目录执行：

```powershell
cd desktop
npm start
```

服务默认监听 `0.0.0.0:8787`，启动日志会输出电脑本机地址和局域网地址，例如：

```text
http://localhost:8787/?token=token_replace_with_random_value
http://192.168.1.31:8787/?token=token_replace_with_random_value
```

电脑浏览器使用 `localhost` 地址，手机浏览器使用局域网 IP 地址。

## API

- `GET /codex/health`：服务健康检查。
- `GET /codex/threads`：读取 Codex Desktop 当前打开的线程列表。
- `GET /codex/history?thread=<id>`：读取指定线程历史。
- `GET /codex/status?thread=<id>&since=<iso-time>`：读取指定时间之后的回复状态。
- `POST /send`：发送消息到指定 Codex Desktop 线程。
- `POST /codex/stop`：向 Codex Desktop 发送停止回复指令。

## 验证

```powershell
npm test
npm run check
```

## 注意事项

- 当前正式控制链路使用 Codex Desktop 内置 App Server，不使用 `codex://threads/<id>` 或 CDP UI 自动化。
- 如果 App Server 未就绪，发送会直接失败并返回错误；应检查内置 `codex.exe` 解析路径和 Codex Desktop 安装状态。
- 不包含自动兜底控制路径；新增其他控制策略前需要先确认。
